# GigaRest

Режим отдыха для Windows 10/11 x64. Одна кнопка «Работа → Отдых»:
- рабочие программы вежливо закрываются, и освобождается память;
- уведомления затихают;
- на основном мониторе (4K OLED 165 Гц) — спокойная сцена;
- на втором мониторе — до 4 живых плиток разрешённых окон (Telegram, личный браузер, Claude, музыка).

Возврат одной кнопкой: всё открывается как было. Личный некоммерческий проект Романа (Luchano55).

Читать первым: ТЗ. Оно личное и в репозиторий не кладётся: Роман прикладывает файл в чат. Сохранить его как `docs/spec.md` (файл в `.gitignore`, не коммитить). Технические решения с источниками — `docs/decisions.md`. Открытые вопросы к Роману — `docs/questions.md`.

## Общение с Романом

- Роман не программист. Писать по-русски, коротко, без жаргона, в форме: **что сделано → что дальше → что нужно от него**.
- Для проверки на Windows — пошаговая инструкция: что скачать, что запустить, куда нажать.
- **Каждый отчёт о новой сборке — со ссылкой на скачивание** (правило Романа): тестовая сборка — установщик https://github.com/Luchano55/gigarest/releases/download/dev-build/GigaRest-Setup.exe (zip без установки: https://github.com/Luchano55/gigarest/releases/download/dev-build/GigaRest-win-x64.zip); стабильная версия — https://github.com/Luchano55/gigarest/releases/latest/download/GigaRest-Setup.exe (выпуск — тегом `vX.Y.Z`, D-RELEASE) — CI обновляет её после каждой зелёной сборки из `main` и `claude/*` (D-RELEASE). Давать ссылку только после того, как сборка с изменениями прошла. Программа обновляется и сама.
- Коммиты — на русском.
- Не упоминать чужие продукты как образец в README и документации.
- Токены и секреты никогда не просить в чат и не класть в репозиторий.
- Репозиторий публичный: чужой арт (обои из игр, трейлеры) сюда не кладётся. Только свои или CC0 картинки. Личные сцены Романа живут у него в папке «Мои сцены».

## Стек

- C# + .NET 8. Интерфейс — WinUI 3 (Windows App SDK, без упаковки MSIX). Сцена и частицы — Win2D. Видео — системный MediaPlayer, аппаратное декодирование.
- Почему не WPF: рывки на 144–165 Гц и VRR, потолок около 60 кадров/с (`docs/decisions.md`, D-UI).
- `src/GigaRest.Core/` (net8.0, без UI): правила закрытия, сессия, настройки, разбор библиотек игр, геометрия плиток, таймеры OLED. Всё под тестами xUnit, собирается на Linux.
- `src/GigaRest.App/` (WinUI 3) собирается только на Windows — в GitHub Actions.
- Настройки: `%AppData%\GigaRest\settings.json`; сессия: `session.json`; журнал: `%AppData%\GigaRest\logs\`.

## Окружение разработки

- **Облачная сессия — Linux.** Здесь собирается и тестируется только ядро. Интерфейс собирает CI на Windows и кладёт скриншоты в ветку `screenshots`.
- **.NET 8 SDK** брать из packages.microsoft.com, ставить в `/opt/dotnet-ms` со ссылкой `/usr/local/bin/dotnet`. Так сделано в соседнем проекте Романа, `Luchano55/dropwheel`, решение D15: у сборки Ubuntu нет WindowsDesktop SDK.
- **Рабочие ветки** — `claude/*`. В `main` только то, что прошло CI.
- **Готовые решения из DropWheel** (`Luchano55/dropwheel`) можно смотреть и переносить: сборка CI, самообновление по `version.json`, установщик Inno Setup, выпуск в winget, окно «Что нового». Это тот же автор и та же лицензия.
- **Макеты** — холст claude.ai: https://claude.ai/artifact/EFaBAJ8ziDg3sSYKWuiVqz. Читать инструментом Artifact (action `read`). Утверждены: «Тихий», «Второй монитор · живые плитки», «Переключатель». Встроенные пейзажи для сцен — `assets/scenes/`.

## Правила работы

- Начинать с этапа 1 (ТЗ, раздел 11); перед этапом — короткий план, после — что проверено автоматически и что проверить вручную.
- **Ничего не завершать принудительно**, кроме программ, где Роман сам поставил галочку «можно завершать», и никогда — при открытом вопросе «Сохранить?». Единственное исключение — программы с галочкой «завершать принудительно, даже если есть несохранённое» (решение Романа, D-CLOSE). У пользователя ничего не удалять.
- **Без прав администратора.** Сеть — только для проверки обновлений.
- **Пути.** Все пути — с кириллицей и пробелами. Аргументы процессов передавать через `ArgumentList`, не склейкой строк.
- **Хуки и системные события** — в отдельных классах, обработчик быстрый, тяжёлое — в другой поток, при выходе всё снимается.
- **Каждая новая функция** — скриншот в README и запись в `docs/CHANGELOG.md`.
